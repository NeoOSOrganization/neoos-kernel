# WM Glass Lensing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `neoos-wm` composite `WM_SURFACE_GLASS` surfaces as Apple-style Liquid Glass -- a real per-pixel refraction lens over the captured backdrop, plus tint -- not a flat translucency blend, by closing sub-project 1's unused-fragment-input gap in `neoos-tinygl` and giving the compositor a two-pass repaint that draws through TinyGL's shader stage.

**Architecture:** Two independent pieces of work land together. (1) `neoos-tinygl`'s SPIR-V VM (`spv_vm.c`) currently ignores the `inputs`/`ninputs` a fragment shader is called with; this plan adds real `OpVariable`(Input)/`OpDecorate`(Location) parsing to `spv_module.c` so `spv_vm_run_fragment` can bind a per-pixel varying to the SPIR-V id a shader actually loads from -- verified with fast host-native tests, no QEMU. (2) `neoos-wm` gains a new surface flag, links `neoos-tinygl` as a library, opens ONE persistent TinyGL context whose render target IS `wm`'s own `back` compositing buffer (their pixel formats are identical), and splits `repaint()` into two passes: ordinary compositing, then a glass pass that snapshots each glass surface's rect out of `back`, binds it as the shader's input texture, and draws a shaded quad back into that exact rect via `glViewport` -- verified with headless-QEMU serial-log and framebuffer-checksum tests, matching every other NeoOS milestone.

**Tech Stack:** C (gnu99/gnu11), `x86_64-elf-gcc` freestanding cross-compile for target code, host `gcc` for the SPIR-V VM's own test cycle, `spirv-as` to assemble hand-written `.spvasm` fixtures and the built-in shaders into `.spv` binaries (this environment has `spirv-as` but not `glslang`/`glslangValidator`, so shaders are authored directly in SPIR-V assembly -- the same thing sub-project 1's own fixtures already do).

**Spec:** `docs/superpowers/specs/2026-09-20-wm-glass-lensing-design.md`

## Global Constraints

- No wire message ever lets a client hand the compositor shader bytecode -- built-in `.spv` only, embedded at build time. (spec section 4)
- Unsupported/rejected `.spv` at compositor startup, oversized snapshot allocation, or a zero-size/off-screen glass rect: log and fall back to drawing that surface without the glass pass, never crash or freeze the whole compositor. (spec "Error handling")
- Fixed-function (non-glass) window compositing must produce byte-identical output to before this plan when no surface requests `WM_SURFACE_GLASS`, and neoos-tinygl's existing `spvtest` fixtures must keep passing unchanged after Task 2. (spec Goals/Testing)
- `upstream/` in neoos-tinygl stays vendored-unmodified -- every change in this plan touches only `spv/` (neoos-tinygl) or files that already belong to neoos-wm/NeoOS.
- Accepted, NOT fixed by this plan: glass surfaces always composite as if above every non-glass window regardless of true connection order (spec section 2, "Known limitation"). Do not attempt to fix this.

```c
static spv_value_t reg_read(const TGLspvModule *mod, spv_regfile_t *rf, uint32_t id) {
    if (id < SPV_MAX_REGS && rf->has_reg[id]) return rf->regs[id];
    if (spv_module_has_const(mod, id)) {
        spv_value_t v;
        memset(&v, 0, sizeof(v));
        for (int c = 0; c < 16; c++) v.v[c] = spv_module_const_f32(mod, id, c);
        return v;
    }
    int loc = spv_module_input_location(mod, id);
    if (loc >= 0 && g_inputs != NULL && loc < g_ninputs) {
        return g_inputs[loc];
    }
    spv_value_t zero;
    memset(&zero, 0, sizeof(zero));
    return zero;
}
```

- [ ] **Step 4: Set/clear `g_inputs`/`g_ninputs` around each run**

```c
void spv_vm_run_fragment(const TGLspvModule *mod, const spv_value_t *inputs,
                          int ninputs, spv_value_t *output) {
    spv_regfile_t rf;
    memset(&rf, 0, sizeof(rf));
    g_inputs = inputs;
    g_ninputs = ninputs;

    uint32_t out_var = 0;
    run_function(mod, &rf, &out_var);

    g_inputs = NULL;
    g_ninputs = 0;

    if (out_var && out_var < SPV_MAX_REGS)
        *output = rf.regs[out_var];
    else
        memset(output, 0, sizeof(*output));
}

void spv_vm_run_vertex(const TGLspvModule *mod, const spv_value_t *inputs,
                        int ninputs, spv_value_t *output) {
    spv_vm_run_fragment(mod, inputs, ninputs, output);
}
```

## Task 5: Link neoos-tinygl into wm.c, open a persistent shared-buffer TinyGL context

> **ACTUAL EXECUTION NOTE (recorded after the fact):** this task's plan
> as originally written -- "just add `-lm`" -- was wrong. Executing it
> hit a real blocker: TinyGL's `gl_malloc` is musl's `malloc`, and
> musl's `malloc` needs musl's own runtime init (TLS, locks) to have
> run first. `wm.c` boots via `neoos-libneoos`'s `crt0.o`, which never
> runs that init, so `ZB_open`'s first allocation crashed with a
> NULL-pointer dereference (`cr2=0`) -- confirmed by bisection with
> diagnostic printfs, not guessed. Presented to the user as a choice
> between a self-contained heap allocator (smaller, stays on
> libneoos) and porting `wm.c` onto musl's `crt1.o` (larger, matches
> neoos-tinygl's own `spvtest`/`glgears` pattern); the user chose the
> port. It turned out smaller than expected: musl's syscall shim
> already supports every socket call `wm.c` needs (confirmed by
> reading `neoos-musl/upstream/src/internal/neoos_syscall.c` --
> `LX_SOCKET`/`BIND`/`CONNECT`/`SENDMSG`/`RECVMSG`/`ACCEPT4`/etc. are
> all wired), so the only real rewrite was `read_exact_fd` moving from
> a hand-rolled `neo6()`/`k_msghdr_u`/`k_cmsghdr_u` syscall to musl's
> real `recvmsg()` + `CMSG_*` macros -- a simplification, not just a
> port. `wmclient.c`/`wmdemo.c` are unaffected (separate processes,
> stay on libneoos). Porting also surfaced a second, related bug: the
> boot-time client-connect race (previously a rare, documented flake)
> became a near-always-loses race once `screen_open()` got slower
> (TinyGL's depth-buffer allocation) -- fixed by reordering
> `listen_open()` before `screen_open()` in `main()`, so a client's
> `connect()` lands in the accept backlog immediately. See the
> `neoos-wm` commit `wm: port to musl (crt1.o), link neoos-tinygl for
> glass lensing` for the actual diff. The steps below are left as
> originally written for the historical record of what was planned;
> follow the commit's real approach, not the `-lm`-only steps below.

- [ ] **Step 1: Author the vertex shader**

`neoos-wm/glass_shaders/glass_vertex.spvasm` -- passes clip position
through unchanged. It does NOT need to emit a UV varying: tracing
`spv_gl_fill_triangle` (`neoos-tinygl/spv/spv_gl.c`) shows the `u,v`
the fragment shader receives comes entirely from TinyGL's own
fixed-function texcoord interpolation (`ZBufferPoint.s`/`.t`,
barycentric-interpolated from whatever `glTexCoord2f` calls preceded
each `glVertex3f`) -- it is independent of anything the vertex SPIR-V
program outputs. The vertex stage's only observable job here is
clip-space position:

```
               OpCapability Shader
               OpMemoryModel Logical GLSL450
               OpEntryPoint Vertex %main "main" %pos_in %pos_out
        %void = OpTypeVoid
        %fnty = OpTypeFunction %void
       %float = OpTypeFloat 32
        %vec4 = OpTypeVector %float 4
   %ptr_in_v4 = OpTypePointer Input %vec4
   %ptr_out_v4 = OpTypePointer Output %vec4
               OpDecorate %pos_in Location 0
               OpDecorate %pos_out Location 0
     %pos_in = OpVariable %ptr_in_v4 Input
    %pos_out = OpVariable %ptr_out_v4 Output
        %main = OpFunction %void None %fnty
       %entry = OpLabel
           %p = OpLoad %vec4 %pos_in
                OpStore %pos_out %p
                OpReturn
                OpFunctionEnd
```

(`spv_gl_run_vertex` supplies `attribs[0..3]` as `inputs[0]` and reads
`output` straight back as the 4-float clip position -- this pass-through
is the minimum valid vertex program; sub-project 1's own fixture set
never needed more than this either.)

- [ ] **Step 2: Author the fragment shader**

`neoos-wm/glass_shaders/glass_fragment.spvasm` -- reads the
interpolated position-as-UV varying (Location 0, matching Task 2's
`spv_gl_fill_triangle` which supplies the rasterizer's per-pixel `u,v`
at `inputs[0].v[0..1]`, already in `0..1` range), computes a
center-biased refraction offset, samples the bound backdrop texture at
the displaced coordinate, multiplies by a constant tint, and stores
the result:

```
               OpCapability Shader
               OpMemoryModel Logical GLSL450
               OpEntryPoint Fragment %main "main" %uv %out_color
               OpExecutionMode %main OriginUpperLeft
               OpDecorate %uv Location 0
               OpDecorate %out_color Location 0
        %void = OpTypeVoid
        %fnty = OpTypeFunction %void
       %float = OpTypeFloat 32
        %vec2 = OpTypeVector %float 2
        %vec4 = OpTypeVector %float 4
      %img_t = OpTypeImage %float 2D 0 0 0 1 Unknown
     %simg_t = OpTypeSampledImage %img_t
   %ptr_simg = OpTypePointer UniformConstant %simg_t
        %tex = OpVariable %ptr_simg UniformConstant
   %ptr_in_v4 = OpTypePointer Input %vec4
         %uv = OpVariable %ptr_in_v4 Input
   %ptr_out_v4 = OpTypePointer Output %vec4
   %out_color = OpVariable %ptr_out_v4 Output
       %half = OpConstant %float 0.5
    %strength = OpConstant %float 0.06
       %tintr = OpConstant %float 0.92
       %tintg = OpConstant %float 0.97
       %tintb = OpConstant %float 1.0
       %tinta = OpConstant %float 1.0
       %tint = OpConstantComposite %vec4 %tintr %tintg %tintb %tinta
        %main = OpFunction %void None %fnty
       %entry = OpLabel
       %uv4 = OpLoad %vec4 %uv
                                        ; centered = uv - 0.5, per component, via FSUB against a broadcast half
       %halfv = OpCompositeConstruct %vec4 %half %half %half %half
   %centered = OpFSub %vec4 %uv4 %halfv
                                        ; offset = centered * strength (broadcast scalar via VectorTimesScalar)
    %offset = OpVectorTimesScalar %vec4 %centered %strength
   %sampleuv4 = OpFAdd %vec4 %uv4 %offset
                                        ; OpImageSampleImplicitLod's coordinate operand is read as .xy by the VM
         %s = OpLoad %simg_t %tex
     %sample = OpImageSampleImplicitLod %vec4 %s %sampleuv4
   %shaded = OpFMul %vec4 %sample %tint
                OpStore %out_color %shaded
                OpReturn
                OpFunctionEnd
```

This is the refraction-offset + uniform-tint effect from the spec:
`strength = 0.06` biases the sample point away from center, growing
with distance from the quad's middle (since `centered` grows toward
the edges), and `tint` is the constant frosted-glass multiply.
`OpImageSampleImplicitLod`'s coordinate operand only needs `.xy`
populated (the VM's existing implementation, verified in sub-project
1, reads `coord.v[0]`/`coord.v[1]`) -- `sampleuv4`'s `.zw` components
are along for the ride unused, which is fine since `spv_value_t` is
always a full 4-float slot.

**Files:**

**Interfaces:**

- [ ] **Step 1: Add the snapshot + shade helper**

In `wm.c`, add a new static function near `draw_window`/`repaint`:

```c
// Snapshots `c`'s full extent (including decoration, same rect
// damage_window computes) out of `back`, converts it to RGBA8, binds
// it as the shader's input texture, and draws a shaded quad back into
// that exact rect -- TinyGL's render target IS `back` (Task 5), so no
// separate copy-back is needed.
static void draw_glass(struct client *c) {
    if (!c->mapped || !g_glass_zb || !g_glass_vs || !g_glass_fs) { return; }

    int x = c->is_shell ? c->x : c->x - BORDER;
    int y = c->is_shell ? c->y : c->y - TITLE_H - BORDER;
    int w = c->is_shell ? (int)c->w : (int)c->w + 2 * BORDER;
    int h = c->is_shell ? (int)c->h : (int)c->h + TITLE_H + 2 * BORDER;
    if (x < 0) { w += x; x = 0; }
    if (y < 0) { h += y; y = 0; }
    if (x + w > (int)fb_w) { w = (int)fb_w - x; }
    if (y + h > (int)fb_h) { h = (int)fb_h - y; }
    if (w <= 0 || h <= 0) { return; }   // off-screen or zero-size -- skip, per spec error handling

    static unsigned char snapshot[/* worst case */ 4096 * 4];
    // Worst-case single-row scratch: convert one row at a time to
    // avoid a second full-screen-sized heap buffer. tglTexImage2D's
    // arbitrary-size VM-level bind (spv_vm_bind_texture) still wants
    // the WHOLE snapshot contiguous, so use a heap allocation sized to
    // this rect instead of the fixed-size row buffer above -- replace
    // the `static unsigned char snapshot[...]` line with:
    unsigned char *snap = malloc((size_t)w * (size_t)h * 4);
    if (!snap) {
        printf("[wm] glass: snapshot allocation failed for a %dx%d surface -- rendering opaque\n", w, h);
        return;
    }
    for (int row = 0; row < h; row++) {
        const uint32_t *src = back + (uint64_t)(y + row) * fb_w + x;
        unsigned char *dst = snap + (uint64_t)row * w * 4;
        for (int col = 0; col < w; col++) {
            uint32_t px = src[col];
            dst[col * 4 + 0] = (px >> 16) & 0xff;  // R
            dst[col * 4 + 1] = (px >> 8) & 0xff;   // G
            dst[col * 4 + 2] = px & 0xff;          // B
            dst[col * 4 + 3] = 255;
        }
    }

    spv_vm_bind_texture(snap, w, h);
    tglUseSpvProgram(g_glass_vs, g_glass_fs);
    glViewport(x, y, w, h);
    // glTexCoord2f per corner is what makes u,v vary per pixel at
    // all -- spv_gl_fill_triangle interpolates THESE (via TinyGL's
    // own fixed-function texcoord pipeline, s/t on each
    // ZBufferPoint), not anything the vertex SPIR-V program outputs
    // (see Task 6 Step 1). Skipping this would hand the fragment
    // shader the same constant UV everywhere, silently defeating
    // Tasks 1-2's whole point.
    glBegin(GL_QUADS);
    glTexCoord2f(0, 0); glVertex3f(-1, -1, 0);
    glTexCoord2f(1, 0); glVertex3f(1, -1, 0);
    glTexCoord2f(1, 1); glVertex3f(1, 1, 0);
    glTexCoord2f(0, 1); glVertex3f(-1, 1, 0);
    glEnd();
    tglUseSpvProgram(NULL, NULL);

    free(snap);
}
```

(Remove the dead `static unsigned char snapshot[...]` line and its
comment block -- it was reasoning-in-progress above, not code to keep;
the `malloc`-based `snap` is the actual implementation. Include
`<stdlib.h>` if `wm.c` does not already.)

- [ ] **Step 2: Split `repaint()` into two passes**

Replace `repaint()`'s existing body (the single loop over shell, then
non-shell clients) with:

```c
static void repaint(void) {
    if (!dmg_any) { screen_dirty = 0; return; }

    fill(0, 0, (int)fb_w, (int)fb_h, 0x00202830);      // desktop
    // Pass 1: every non-glass surface, exactly as before.
    for (int i = 0; i < MAX_CLIENTS; i++) {
        if (clients[i].fd >= 0 && clients[i].is_shell && !clients[i].is_glass) { draw_window(&clients[i], 0); }
    }
    for (int i = 0; i < MAX_CLIENTS; i++) {
        if (clients[i].fd >= 0 && !clients[i].is_shell && !clients[i].is_glass) {
            draw_window(&clients[i], i == focus_slot);
        }
    }
    // Pass 2: glass surfaces, bottom-to-top in slot order -- snapshot
    // the current `back`, shade it, then draw the surface's own
    // attached content on top (same content-blit loop draw_window
    // uses), per spec section 2.
    for (int i = 0; i < MAX_CLIENTS; i++) {
        if (clients[i].fd >= 0 && clients[i].is_glass) {
            draw_glass(&clients[i]);
            draw_window(&clients[i], i == focus_slot);
        }
    }
    draw_cursor();

    for (int y = dmg_y0; y < dmg_y1; y++) {
        const uint32_t *src = back + (uint64_t)y * fb_w + dmg_x0;
        uint32_t *dst = fb + (uint64_t)y * fb_stride_px + dmg_x0;
        for (int x = 0; x < dmg_x1 - dmg_x0; x++) { dst[x] = src[x]; }
    }
    dmg_any = 0;
    screen_dirty = 0;
}
```

`draw_window` already no-ops for an unmapped surface or one with no
`px` -- calling it a second time for glass clients (after
`draw_glass`) is exactly the "content drawn on top of the lensed
backdrop" step the spec's section 2 describes; for a glass surface
with no attached buffer at all (pure chrome), `draw_window` draws
nothing further, which is correct.

Note `draw_window`'s decoration-drawing branch (`if (!c->is_shell)`)
still runs for a glass client that is not the shell -- decoration
stays a flat-color border/title bar even on a glass window, matching
the spec's "otherwise behaves like a normal window" framing.
