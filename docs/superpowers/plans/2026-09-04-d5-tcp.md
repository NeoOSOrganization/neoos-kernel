# D5 — TCP: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use
> `superpowers:executing-plans`. Steps use `- [ ]` checkboxes.

**Goal:** `socket(AF_INET, SOCK_STREAM, 0)` works — a program on NeoOS
accepts a connection, and a program on NeoOS opens one to a host on the
other side of the NIC.

**Architecture:** a fixed array of 64 TCBs hashed by 4-tuple, with the
full eleven-state machine, a Reno congestion controller, and a dedicated
`tcp_timer` kernel thread driving retransmission, delayed ACK, persist
and TIME_WAIT. The state machine (`tcp.c`) is split from the syscall
surface (`tcp_sock.c`) because they fail differently and are read at
different times: one answers "what does the wire mean", the other
answers "what does `accept` return".

**Tech Stack:** C11 freestanding. Loopback carries the deterministic
suite; QEMU slirp carries the interoperability test against a host-side
echo server. A compiled-in fault injector supplies the loss the emulator
never produces.

**Spec:** `docs/superpowers/specs/2026-09-04-d2-d5-network-stack-design.md` §6

## Global Constraints

- **Depends on D2, D3 and D4.**
- **Linux-shaped ABI, without exception.** `listen`/`accept`/`accept4`/
  `shutdown`/`getpeername`/`setsockopt`/`getsockopt` take Linux's
  argument order and return Linux's errnos; `SOL_SOCKET`(1),
  `SO_REUSEADDR`(2), `SO_ERROR`(4), `SO_SNDBUF`(7), `SO_RCVBUF`(8),
  `IPPROTO_TCP`(6), `TCP_NODELAY`(1) take Linux's values. Every one gets
  a musl shim entry and a `docs/stdlib.md` line, per `CLAUDE.md`.
- **MSL = 5 s** (TIME_WAIT 10 s) — a divergence, recorded in
  `docs/stdlib.md`. 60 s cannot be observed inside a 150 s boot that
  also runs forty other suites.
- **`SO_SNDBUF`/`SO_RCVBUF` are reported, not honoured.** The buffers
  are fixed at 64 KB. Recorded as a divergence. An unknown option
  returns `-ENOPROTOOPT` rather than succeeding silently.
- **`LOCK_RANK_TCP`** sits between `LOCK_RANK_SOCKET` and
  `LOCK_RANK_NETRX`. It is taken by the netrx thread, the tcp_timer
  thread, and syscall threads. It never sleeps and is never held across
  `virtio_net_transmit`.
- **No allocation on the receive path.** A SYN flood exhausts a fixed
  table and refuses; it does not exhaust the heap and panic.
- **Every TCB carries a 16-entry state-transition ring**, dumped on the
  establishment timeout and on `tcp_dump()`. TCP's failure mode is a
  hang, not a fault: without this, a wrong transition is a missing
  marker 150 seconds later with nothing in the log.

### Task 1: The header, the checksum, and RST — a connection can be refused

Refusal before establishment, deliberately: `ECONNREFUSED` is the first
thing a client sees when anything is wrong, and a stack that hangs
instead of refusing is undebuggable from the first minute.

**Files:** Create `kernel/net/tcp.h`, `kernel/net/tcp.c`; modify
`kernel/net/net.c` (protocol dispatch), `kernel/net/net.h`
(`ip_pseudo_sum`), `kernel/sync/lock.h`

**Interfaces:**
- Produces:
```c
#define IPPROTO_TCP 6

#define TCP_FIN 0x01
#define TCP_SYN 0x02
#define TCP_RST 0x04
#define TCP_PSH 0x08
#define TCP_ACK 0x10
#define TCP_URG 0x20

struct tcp_header {
    uint16_t sport_n, dport_n;
    uint32_t seq_n, ack_n;
    uint8_t  data_off;        // high nibble: header words
    uint8_t  flags;
    uint16_t window_n;
    uint16_t checksum_n;
    uint16_t urgent_n;
} __attribute__((packed));    // 20 bytes, static_asserted

void tcp_input(struct netdev *dev, const struct ipv4_header *ip,
               const uint8_t *seg, uint32_t len);
void tcp_init(void);
void tcp_selftest(void);
uint64_t tcp_rst_tx(void);    // for the selftest
```
Also generalise `udp_pseudo_sum` in `net.c` into
`uint32_t ip_pseudo_sum(uint32_t src_n, uint32_t dst_n, uint8_t proto, uint16_t len)`
in `net.h`, and make UDP call it. One pseudo-header implementation, two
protocols.

- [ ] **Step 1: Write the failing selftest** (`tcp_selftest`, part 1):

```c
// A segment for a port nothing listens on must produce a RST, with the
// ACK derivation the RFC requires: for a segment carrying no ACK, the
// RST's seq is 0 and its ack is seg.seq + seg.len + (SYN ? 1 : 0).
uint64_t before = tcp_rst_tx();
inject_syn(/*sport*/ 40000, /*dport*/ 9999, /*seq*/ 0x11223344);
if (tcp_rst_tx() != before + 1) {
    serial_write_string("[tcp] FAILED: a SYN to a closed port was silent\n");
    failed = 1;
}
const struct tcp_header *r = tcp_last_tx();
if (!(r->flags & TCP_RST) || !(r->flags & TCP_ACK)) {
    serial_write_string("[tcp] FAILED: RST for a SYN must also carry ACK\n");
    failed = 1;
}
if (ntohl_k(r->ack_n) != 0x11223345u) {
    serial_write_string("[tcp] FAILED: RST ack does not consume the SYN\n");
    failed = 1;
}
// A RST must NEVER be answered with a RST.
before = tcp_rst_tx();
inject_rst(40000, 9999, 0x55667788);
if (tcp_rst_tx() != before) {
    serial_write_string("[tcp] FAILED: answered a RST with a RST\n");
    failed = 1;
}
// A segment with a bad checksum is dropped silently -- no RST.
before = tcp_rst_tx();
inject_syn_bad_checksum(40000, 9999, 0x99AABBCC);
if (tcp_rst_tx() != before) {
    serial_write_string("[tcp] FAILED: RST'd a corrupt segment\n");
    failed = 1;
}
```

The RST-for-RST case is the one worth writing down: getting it wrong
produces an infinite exchange between two hosts that is invisible until
someone looks at a capture.

- [ ] **Step 2: Run and watch it fail.**
- [ ] **Step 3:** Implement the header, `ip_pseudo_sum`, checksum

- [ ] **Step 4: `make test`;** part 1 passes.
- [ ] **Step 5: Prove the detectors** — (a) drop the `+1` for SYN →
      `RST ack does not consume the SYN`; (b) remove the RST-inbound

### Task 2: The TCB table and the state machine

**Files:** Modify `kernel/net/tcp.c`, `kernel/net/tcp.h`

**Interfaces:**
- Produces:
```c
#define TCP_MAX_CONNS   64
#define TCP_SNDBUF      65536
#define TCP_RCVBUF      65536
#define TCP_REASM_SEGS  8
#define TCP_BACKLOG_MAX 8
#define TCP_MSL_TICKS   (5 * TIMER_HZ)

enum tcp_state {
    TCP_CLOSED, TCP_LISTEN, TCP_SYN_SENT, TCP_SYN_RECEIVED,
    TCP_ESTABLISHED, TCP_FIN_WAIT_1, TCP_FIN_WAIT_2, TCP_CLOSE_WAIT,
    TCP_CLOSING, TCP_LAST_ACK, TCP_TIME_WAIT,
};

struct tcb {
    enum tcp_state state;
    uint32_t local_n, remote_n;
    uint16_t lport_n, rport_n;
    // send sequence space
    uint32_t snd_una, snd_nxt, snd_wnd, snd_wl1, snd_wl2, iss;
    // receive sequence space
    uint32_t rcv_nxt, rcv_wnd, irs;
    uint16_t mss;
    // buffers: rings, not queues. Fixed, so nothing allocates on rx.
    uint8_t  sndbuf[TCP_SNDBUF]; uint32_t snd_head, snd_tail;
    uint8_t  rcvbuf[TCP_RCVBUF]; uint32_t rcv_head, rcv_tail;
    struct tcp_reasm { uint32_t seq, len; uint8_t data[1460]; int used; }
             reasm[TCP_REASM_SEGS];
    // timers, in ticks; 0 means disarmed
    uint64_t rto_deadline, delack_deadline, persist_deadline,
             timewait_deadline, establish_deadline;
    uint32_t rto_ticks, srtt, rttvar;     // Jacobson/Karels, in ticks*8
    uint32_t rtt_seq; uint64_t rtt_at;    // the sample in flight; Karn
    uint8_t  retries;
    // congestion control
    uint32_t cwnd, ssthresh, dupacks; int in_recovery; uint32_t recover;
    // listen
    int backlog; struct tcb *accept_q[TCP_BACKLOG_MAX]; int accept_n;
    struct tcb *parent;
    // flags and lifetime
    int nodelay, reuseaddr, so_error, refs, fin_sent, fin_rcvd;
    struct waitq waiters;
    struct poll_head poll;
    uint8_t  trace[16]; int trace_n;      // state ring; TCP hangs, it does not fault
};

struct tcb *tcp_find(uint32_t local_n, uint16_t lport_n,
                     uint32_t remote_n, uint16_t rport_n);
```

- [ ] **Step 1: Extend the selftest** with a state-machine table driven
      by injection, asserting every transition the RFC names — including
      **simultaneous open** (SYN_SENT + inbound SYN → SYN_RECEIVED) and
      **simultaneous close** (FIN_WAIT_1 + inbound FIN → CLOSING →
      TIME_WAIT). Both are three lines each in a machine that already
      exists and are a well-known source of hangs when omitted:

```c
static const struct { const char *name; int from, flags, to; } transitions[] = {
    { "LISTEN + SYN -> SYN_RECEIVED",         TCP_LISTEN,      TCP_SYN,           TCP_SYN_RECEIVED },
    { "SYN_SENT + SYN|ACK -> ESTABLISHED",    TCP_SYN_SENT,    TCP_SYN|TCP_ACK,   TCP_ESTABLISHED  },
    { "SYN_SENT + SYN -> SYN_RECEIVED",       TCP_SYN_SENT,    TCP_SYN,           TCP_SYN_RECEIVED },
    { "SYN_RECEIVED + ACK -> ESTABLISHED",    TCP_SYN_RECEIVED,TCP_ACK,           TCP_ESTABLISHED  },
    { "ESTABLISHED + FIN -> CLOSE_WAIT",      TCP_ESTABLISHED, TCP_FIN|TCP_ACK,   TCP_CLOSE_WAIT   },
    { "FIN_WAIT_1 + ACK -> FIN_WAIT_2",       TCP_FIN_WAIT_1,  TCP_ACK,           TCP_FIN_WAIT_2   },
    { "FIN_WAIT_1 + FIN -> CLOSING",          TCP_FIN_WAIT_1,  TCP_FIN|TCP_ACK,   TCP_CLOSING      },
    { "FIN_WAIT_2 + FIN -> TIME_WAIT",        TCP_FIN_WAIT_2,  TCP_FIN|TCP_ACK,   TCP_TIME_WAIT    },
    { "CLOSING + ACK -> TIME_WAIT",           TCP_CLOSING,     TCP_ACK,           TCP_TIME_WAIT    },
    { "LAST_ACK + ACK -> CLOSED",             TCP_LAST_ACK,    TCP_ACK,           TCP_CLOSED       },
};
```

For each row: force a TCB into `from`, inject a segment with `flags`
and correct sequence numbers, assert the state is `to`, and on failure
print the row's `name` **and** dump the TCB's trace ring.

- [ ] **Step 2: Run; watch it fail.**
- [ ] **Step 3:** Implement the table, the 4-tuple hash, and
      `tcp_input`'s segment-acceptability test (RFC 793 §3.9's four
      cases on window and sequence), then the state machine.
- [ ] **Step 4:** ISN from the existing random source, **not** a
      counter.
- [ ] **Step 5: `make test`;** every transition passes.
- [ ] **Step 6: Prove the detector** — delete the CLOSING row's handler;
      confirm `FIN_WAIT_1 + FIN -> CLOSING` fires with a trace dump;
      revert.
- [ ] **Step 7: Commit.**

```bash
git add kernel/net/tcp.c kernel/net/tcp.h
git commit -m "tcp: the state machine, including the simultaneous cases"
```

### Task 3: Data transfer — rings, reassembly, Nagle, delayed ACK

**Files:** Modify `kernel/net/tcp.c`; create `kernel/net/tcp_timer.c`

- [ ] **Step 1: Extend the selftest:**
  - a segment stream delivered **in order** appears byte-exact in the
    receive ring
  - three segments delivered **out of order** (2,3,1) are reassembled
    into the right bytes, and `rcv_nxt` advances exactly once
  - a **ninth** out-of-order segment is dropped and counted, not
    written past the array
  - an out-of-order segment triggers an **immediate** ACK, not a
    delayed one, so the peer's fast retransmit can fire
  - two full-sized in-order segments trigger an ACK without waiting
    200 ms
  - one small segment alone is ACKed only after the delayed-ACK timer
  - with Nagle on, a second small write does **not** leave while the
    first is unacknowledged; with `TCP_NODELAY` set, it does
  - the advertised window shrinks as the ring fills and does not
    advertise an increase smaller than one MSS (silly window)
- [ ] **Step 2: Run; watch it fail.**
- [ ] **Step 3:** Implement the rings, the reassembly array, the
      window computation, Nagle, and the delayed-ACK arm.
- [ ] **Step 4:** Implement `tcp_timer.c`: a kernel thread woken every
      tick that walks the active TCBs and fires the five timers. A
      thread rather than a tick callback because firing a timer
      transmits, transmitting takes the ARP lock and may spin on the
      device, and neither belongs in a timer interrupt.
- [ ] **Step 5: `make test`.**
- [ ] **Step 6: Prove the detectors** — (a) accept a ninth out-of-order
      segment; (b) delay the ACK for an out-of-order segment. Revert.
- [ ] **Step 7: Commit.**

### Task 4: Retransmission, RTO estimation, and the persist timer

**Files:** Modify `kernel/net/tcp.c`, `kernel/net/tcp_timer.c`

- [ ] **Step 1: Extend the selftest:**
  - an unacknowledged segment is retransmitted after the RTO, and the
    RTO **doubles** on each attempt
  - after 12 attempts the connection fails with `ETIMEDOUT` and the
    waiters wake
  - an RTT sample updates `srtt`/`rttvar` per Jacobson/Karels, and the
    resulting RTO stays clamped to [200 ms, 60 s]

    Assert `srtt` is unchanged across a retransmitted exchange — this is

    rather than deadlocking, and the probe carries exactly one byte

### Task 5: Reno congestion control

**Files:** Create `kernel/net/tcp_cc.c`; modify `kernel/net/tcp.h`

**Interfaces:**
- Produces:
```c
void tcp_cc_init(struct tcb *t);          // cwnd = 2*mss, ssthresh = 64K
void tcp_cc_on_ack(struct tcb *t, uint32_t acked);
void tcp_cc_on_dupack(struct tcb *t);     // fast retransmit at the third
void tcp_cc_on_timeout(struct tcb *t);    // ssthresh = max(flight/2, 2*mss)
uint32_t tcp_cc_window(const struct tcb *t);  // min(cwnd, snd_wnd)
```

- [ ] **Step 1: Extend the selftest:**
  - slow start doubles `cwnd` per RTT while below `ssthresh`
  - above `ssthresh`, `cwnd` grows by about one MSS per RTT, not per ACK
  - the **third** duplicate ACK — not the second, not the fourth —
    retransmits and halves `ssthresh`
  - fast recovery inflates `cwnd` per further duplicate and deflates on
    the recovery ACK
  - a timeout sets `cwnd = MSS` and `ssthresh = max(flight/2, 2*MSS)`
  - the amount in flight never exceeds `min(cwnd, snd_wnd)`
- [ ] **Step 2: Run; watch it fail.**
- [ ] **Step 3:** Implement.
- [ ] **Step 4: `make test`.**
- [ ] **Step 5: Prove the detector** — fast-retransmit on the second
      duplicate; confirm the third-dupack assertion fires; revert.
- [ ] **Step 6: Commit.**

### Task 7: `tcptest` — the deterministic loopback suite

**Files:** Create `userland/tcptest.c`; modify `Makefile`,
`userland/init` entry list

This is the suite the milestone actually rests on. It runs over
loopback, so it is deterministic, and it runs in the gauntlet.

- [ ] **Step 1: Write it.** One process, two threads (or a fork), a
      listener on 127.0.0.1 and a client:
  - `listen`/`accept`/`connect` complete and `getpeername` on each side
    matches the other's `getsockname`
  - **a transfer larger than the send buffer** — 256 KB, checked
    byte-exact — so the window actually closes and reopens. A test that
    sends 100 bytes proves nothing about a window
  - full duplex: both directions transferring at once
  - an ordered close: both sides see EOF (`recv` returns 0), and neither
    blocks forever
  - `shutdown(SHUT_WR)`: the peer sees EOF while the reverse direction
    still carries data
  - `connect` to a closed port returns `ECONNREFUSED`, not a hang
  - `connect` under `O_NONBLOCK` returns `EINPROGRESS`, `poll(POLLOUT)`
    fires, and `SO_ERROR` reads 0
  - `TCP_NODELAY` set and read back
  - an unknown sockopt returns `ENOPROTOOPT`
  - a TIME_WAIT connection is observed to expire and its port to become
    reusable (this is why MSL is 5 s)
- [ ] **Step 2: Run; watch it fail.**
- [ ] **Step 3:** Fix whatever it finds. Expect this step to be the
      longest in the plan; it is the first time the whole machine runs
      end to end.
- [ ] **Step 4:** `[tcptest] ALL PASSED` into `REQUIRED_MARKERS`.
- [ ] **Step 5: Commit.**
