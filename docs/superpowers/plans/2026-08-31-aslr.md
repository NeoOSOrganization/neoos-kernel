# ASLR — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Randomize the user address-space layout (mmap base, main
stack, brk, PIE load base) from a real software entropy pool, with a
`norandmaps` off-switch. Replace the LCG that currently backs
`AT_RANDOM`.

**Architecture:** A new `kernel/dev/random.c` mixes RDTSC jitter from
the timer tick and interrupt entry into a 256-bit pool and drains it
through a stream generator. `kernel/mm/aslr.h` exposes
`aslr_offset(bits)` (0 when disabled). Spawn/exec/loader call sites add
the offset to the fixed constants they use today. PIE (`ET_DYN`) load
support is added first, separately from randomizing its base.

**Tech Stack:** C (freestanding), NASM, x86-64, GNU Make, headless
QEMU, the parallel gauntlet (CONC=3).

**Spec:** `docs/superpowers/specs/2026-08-31-aslr-design.md`
**Depends on:** the NX/W^X milestone (loader is touched by both; do
NX/W^X first).

## Global Constraints

- **No host unit tests.** Each task's test is a selftest or userland
  binary; after each task the parallel gauntlet must reach
  `PGAUNTLET PASSED: 15/15` — **with ASLR on** from Task 3 onward.
- **Lock ranks are enforced.** One new leaf lock (`random_lock`), taken
  from IRQ context, holding nothing else — rank `LOCK_RANK_SERIAL`
  (leaf, always legal).
- **The ABI is not ours.** `AT_RANDOM` backing changes (recorded);
  ASLR entropy bits chosen to match Linux x86-64 defaults; a
  `norandmaps` cmdline matching `kernel.randomize_va_space=0`.
- **Work on `main`, one commit per task**, standard trailer.
- **Do not run `make` while the gauntlet runs.**

## Task 1: Entropy pool

**Files:** `kernel/dev/random.c`/`.h` (new), timer ISR, `kernel/arch/isr.c`,
`kernel/kernel.c`, `Makefile`.

**Interfaces — Produces:**
```c
void     random_init(void);
void     random_add_sample(uint64_t x);   // IRQ-safe, leaf-locked
void     random_bytes(void *buf, size_t n);
uint64_t random_u64(void);
void     random_selftest(void);
```

- [ ] **Step 1: failing test**

`random_selftest`: draw 4096 bytes into a buffer; assert not all zero;
count set bits, assert 1600 < popcount < 2496 (≈40-60%); assert
`random_u64() != random_u64()`. Print `[random] selftest FAILED: ...`
or `[random] selftest passed`. Wire the call in `kernel.c`; add the
marker to `REQUIRED_MARKERS`. Build with an **empty** `random.c` (all
functions return 0 / zero the buffer) → `make test` shows
`[random] selftest FAILED: all zero`.

- [ ] **Step 2: implement the pool**

`pool[4]` uint64. `random_add_sample(x)`: `pool[i] ^= x;` then a
splitmix64 mix step on `pool[i]`; `i = (i+1) & 3`; all under
`random_lock` (a `spin_lock_irqsave` leaf). `random_bytes`: seed a
`xoshiro256**` state from `pool` (copy + one mix), generate `n` bytes,
then `random_add_sample(rdtsc())` to fold fresh jitter back. `random_
u64` = 8 bytes of that. `random_init`: 64× `{ rdtsc(); __asm__("pause")
}` fed to `random_add_sample`, then one `random_bytes` throwaway.

- [ ] **Step 3: hooks**

One line in the timer tick path (after the existing tick bookkeeping):
`random_add_sample(rdtsc());`. One line at the top of the ISR dispatch
(`kernel/arch/isr.c`, the common C entry): same. These are cheap and
run with interrupts already off.

- [ ] **Step 4: test passes; gauntlet + commit**

`[random] selftest passed`; gauntlet 15/15. Commit
`"ASLR: software entropy pool (RDTSC jitter), selftest, timer/IRQ hooks"`.

## Task 2: `aslr.h` / `aslr_offset` / `norandmaps` (no call sites yet)

**Files:** `kernel/mm/aslr.c`/`.h` (new), the Multiboot2 cmdline parser.

**Interfaces — Produces:**
```c
#define MMAP_RND_BITS   28
#define STACK_RND_BITS  22
#define BRK_RND_BITS    13
extern int aslr_enabled;
uint64_t aslr_offset(unsigned bits);   // 0 if !aslr_enabled;
                                       // else (random_u64() & ((1u<<bits)-1)) << 12
```

- [ ] **Step 1** — implement; `aslr_enabled = 1` by default. Parse the
  boot cmdline for the token `norandmaps` (space-delimited) and clear
  `aslr_enabled`. Log `[aslr] enabled` / `[aslr] disabled (norandmaps)`.
- [ ] **Step 2** — a trivial selftest: `aslr_offset(0) == 0`;
  `aslr_offset(28)` is page-aligned and `< (1UL<<40)`. Marker
  `[aslr] offset selftest passed`.
- [ ] **Step 3** — gauntlet 15/15 (no behaviour change). Commit
  `"ASLR: aslr_offset, aslr_enabled, norandmaps cmdline"`.

## Task 3: randomize mmap base + AT_RANDOM

**Files:** `kernel/sched/proc.c` (`proc_alloc` mmap_next init;
`build_initial_stack` AT_RANDOM), `userland/aslrtest.c` (new),
`Makefile`.

- [ ] **Step 1: failing test — `aslrtest.c`**

```c
// forks N children; each prints (via a pipe or a shared file) the
// address of a heap malloc(1). Parent asserts they are NOT all equal.
```
Build it, wire a spawn + a `REQUIRED_MARKER` `[aslrtest] mmap varies`.
Run `make test` — today every child prints the same mmap address →
`[aslrtest] FAILED: mmap base identical across 4 children`.

- [ ] **Step 2: implement**

- `proc_alloc` (and any other place that sets `p->mmap_next = MMAP_BASE`):
  `p->mmap_next = MMAP_BASE + aslr_offset(MMAP_RND_BITS);`
- `build_initial_stack` AT_RANDOM: replace the LCG loop with
  `random_bytes((void via poke_user), at_random, 16)` — write 16 real
  random bytes into the user stack. (Poke them one qword at a time as
  today, sourced from `random_u64()`.)

- [ ] **Step 3: test passes with ASLR ON; suite green**

`make test` → `[aslrtest] mmap varies`; **all** existing suites still
`ALL PASSED` (mmaptest, tlstest, etc. must not hard-code an mmap
address). Anything that breaks found a latent assumption — fix it.

- [ ] **Step 4: gauntlet ×1 (ASLR on) + commit**

`"ASLR: randomize mmap base and AT_RANDOM from the entropy pool"`.

## Task 4: randomize the main thread stack

**Files:** `kernel/sched/proc.h` (`p->stack_top_base`),
`kernel/sched/proc.c` (spawn/exec/fork), `kernel/sched/thread.c`
(`thread_stack_top_for` / `thread_stack_alloc`).

- [ ] **Step 1: extend `aslrtest.c`** — each child also prints the
  address of a local `volatile int`. Parent asserts stack addresses
  differ across children. Marker `[aslrtest] stack varies`. FAIL today.

- [ ] **Step 2: implement**

- `struct process` gains `uint64_t stack_top_base;` set once at spawn/
  exec: `stack_top_base = USER_STACK_TOP - aslr_offset(STACK_RND_BITS)`
  (16-byte aligned). `fork_task` copies the parent's value.
- `thread_stack_top_for(p, slot)` (add the `p` parameter, or read
  `current_proc()->stack_top_base`): `return p->stack_top_base - slot *
  THREAD_STACK_STRIDE;`. Update `thread_stack_alloc/free` and the
  `build_initial_stack` caller to use it. The guard-page math is
  unchanged relative to `stack_top_base`.

- [ ] **Step 3: test + suite**

`[aslrtest] stack varies`; `threadtest` (multiple thread stacks),
`sigtest` (sigaltstack), `tlstest` all still green. An overlap here is
a hard crash — watch for `#PF` / double fault in the gauntlet.

- [ ] **Step 4: gauntlet ×3 + commit**

`"ASLR: randomize the main thread stack top"`.

## Task 5: PIE (`ET_DYN`) load support — no randomization yet

**Files:** `kernel/elf.c`, a new `userland/pietest.c` built with
`-fPIE -pie`, `Makefile`.

- [ ] **Step 1** — build `pietest` (`-fPIE -pie -Wl,-z,now`), a
  program that prints "hello from PIE" and the address of `main`. Add
  a spawn + `REQUIRED_MARKER` `[pietest] ran`. Run `make test` →
  today the loader rejects `ET_DYN` or loads it at bias 0 and it
  faults → FAIL.

- [ ] **Step 2** — in `elf_load`: if `e_type == ET_DYN`, pick
  `load_bias = ELF_ET_DYN_BASE` (a fixed constant for now, e.g.
  `0x555555554000` like Linux), add it to every `p_vaddr`, to the
  program-header address, and to `e_entry`. After mapping, walk
  `.rela.dyn` for `R_X86_64_RELATIVE` entries and write
  `*(uint64_t*)(load_bias + r_offset) = load_bias + r_addend`. For
  `ET_EXEC`, `load_bias = 0` (unchanged).

- [ ] **Step 3** — `[pietest] ran`; every existing (`ET_EXEC`) binary
  still loads. Gauntlet 15/15. Commit
  `"ASLR: load ET_DYN (PIE) binaries with a fixed bias + RELATIVE relocs"`.

## Task 6: randomize the PIE load base and brk

**Files:** `kernel/elf.c` (bias), `kernel/sched/proc.c` (brk init).

- [ ] **Step 1** — `pietest` prints `&main`; run it 4× (spawn loop or
  fork), assert the addresses differ → `[aslrtest] pie base varies`.
  Also assert `sbrk(0)` differs across children. FAIL today (fixed
  bias).

- [ ] **Step 2** — `load_bias = ELF_ET_DYN_BASE + aslr_offset(MMAP_RND_BITS)`.
  `p->brk = page_up(bss_end) + aslr_offset(BRK_RND_BITS)` wherever brk
  is initialized (grep `brk`).

- [ ] **Step 3** — markers pass with ASLR on; suite green. Gauntlet
  ×3. Commit `"ASLR: randomize the PIE load base and brk"`.

## Task 7: `test-norandmaps`, docs

- [ ] **Step 1** — `Makefile`: a `test-norandmaps` target identical to
  `test` but appending `norandmaps` to the kernel cmdline. Add a
  variant of `aslrtest` behaviour: when it detects (via a second run
  or an env signal) that ASLR is off, it asserts addresses are
  **identical** across children instead. Simplest: `aslrtest` reads
  `/proc`-less — pass the expectation as `argv[1]` from the spawn line,
  and add both spawn lines under the two Makefile targets. Run
  `make test-norandmaps` once, confirm deterministic layout restored.

- [ ] **Step 2** — `docs/stdlib.md`: `AT_RANDOM` now from the entropy
  pool; layout randomized by default; `norandmaps` disables it; PIE
  supported. `docs/abi-compatibility.md`: entropy bits vs Linux, the
  non-certified pool, PIE `ET_DYN`. `docs/optimization-summary.md`:
  the ASLR entry.

- [ ] **Step 3** — commit `"ASLR: test-norandmaps target and docs"`.
