# x2APIC — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Drive the LAPIC through the x2APIC MSR bank instead of the
xAPIC MMIO window — 32-bit APIC IDs, a single 64-bit ICR write, no
delivery-pending poll — with a working xAPIC fallback.

**Architecture:** `lapic.c` gains a `x2apic_mode` flag set once at
`lapic_init` from `CPUID` + `IA32_APIC_BASE.EXTD`. `lapic_read/write`
and `lapic_send_icr` branch on it. APs set EXTD in their own init.
Everything above `lapic.h` is unchanged.

**Tech Stack:** C (freestanding), NASM, x86-64, GNU Make, headless
QEMU (`-cpu Nehalem,+x2apic`), the parallel gauntlet (CONC=3).

**Spec:** `docs/superpowers/specs/2026-08-31-x2apic-design.md`

## Global Constraints

- **No host unit tests.** IPI correctness is exercised by AP bring-up
  and the `[smp] steal / timer / parallel selftest` lines; a broken
  IPI path hangs the boot or fails a selftest — the gauntlet catches
  it. After each task: `PGAUNTLET PASSED: 15/15`; ×3 after Task 3.
- **Lock ranks:** no new locks.
- **No ABI impact** (LAPIC is kernel-internal).
- **Work on `main`, one commit per task**, standard trailer.
- **`rdmsr`/`wrmsr` live in `kernel/arch/msr.h`** — reuse.

## Task 2: mode detect + MSR accessors (IPIs still MMIO)

**Files:** `kernel/dev/lapic.c`, AP init in `kernel/smp/smp.c`.

**Interfaces — Produces:** `int lapic_x2_mode(void);` (for the boot log
and the selftest).

- [ ] **Step 1: implement detect + enable**

`lapic_init(address)`:
```c
uint32_t a,b,c,d; cpuid(1, &a,&b,&c,&d);
x2apic_capable = (c >> 21) & 1;
uint64_t base = rdmsr(MSR_APIC_BASE);   // 0x1B
if (x2apic_capable) {
    wrmsr(MSR_APIC_BASE, base | (1<<11) | (1<<10));  // EN | EXTD
    x2apic_mode = 1;
    serial_write_string("[lapic] x2apic mode\n");
} else {
    lapic_base = phys_to_virt(address);
    serial_write_string("[lapic] xapic (mmio) mode\n");
}
```
Add both strings to `REQUIRED_MARKERS` **as an alternation** — i.e.
extend the Makefile check to accept `"[lapic] x2apic mode"` OR
`"[lapic] xapic (mmio) mode"` (a small `grep -E` in the marker loop,
or just require the common prefix `"[lapic] "` + a mode word). Pick one
and document it in the Makefile comment.

`lapic_read/write`:
```c
static uint32_t lapic_read(uint32_t reg) {
    if (x2apic_mode) return (uint32_t)rdmsr(0x800 + (reg >> 4));
    return lapic_base[reg / 4];
}
```
`lapic_id()`:
```c
uint32_t v = lapic_read(LAPIC_REG_ID);
return x2apic_mode ? v : (v >> 24);
```
**Keep `lapic_send_icr` on the MMIO path for now** — guard it so that
in x2apic_mode it still writes `ICR_HIGH`/`ICR_LOW`... except those MSRs
don't exist. So actually: in this task, if `x2apic_mode`, ICR must use
the 64-bit MSR (there is no MMIO ICR once EXTD is set). That means Task
2 and Task 3 cannot be fully separated. **Revised:** do the ICR change
here too (it is unavoidable), and Task 3 becomes "verify + drop the
idle poll + self-IPI selftest".

```c
static void lapic_send_icr(uint32_t apic_id, uint32_t low) {
    if (x2apic_mode) { wrmsr(0x830, ((uint64_t)apic_id << 32) | low); return; }
    lapic_write(LAPIC_REG_ICR_HIGH, apic_id << 24);
    lapic_write(LAPIC_REG_ICR_LOW, low);
    lapic_wait_idle();
}
```
`lapic_wait_idle`: early-return in x2apic_mode.

- [ ] **Step 2: AP enable**

In the AP bring-up C entry (grep `syscall_init_this_cpu` neighbours in
`smp.c`), before the AP touches the LAPIC, run the same
`wrmsr(MSR_APIC_BASE, ... | EXTD)` — EXTD is per-CPU. Factor the
enable into `lapic_enable_this_cpu()` called by both BSP and AP paths.

- [ ] **Step 3: build + run**

`make test` — `[lapic] x2apic mode`, all `[smp] * selftest passed`,
`[smptest] ALL PASSED`. AP bring-up (`[smp] cpu N online` ×3) is the
canary: if SIPI via the 64-bit ICR is wrong, APs never start.

- [ ] **Step 4: gauntlet ×1 + commit**

`"x2APIC: MSR LAPIC access + 64-bit ICR; xAPIC fallback"`.

## Task 3: verify IPI paths, self-IPI selftest, fallback build

**Files:** `kernel/dev/lapic.c` (selftest), `kernel/kernel.c` (call).

- [ ] **Step 1: self-IPI selftest**

`lapic_selftest()`: install a handler on a spare vector (e.g. 0xEF),
`lapic_send_ipi(lapic_id(), 0xEF)`, spin briefly on a `volatile`
counter the handler bumps, assert it fired. Print
`[lapic] self-IPI selftest passed`. Add to `REQUIRED_MARKERS`. Runs on
the BSP after `lapic_init`.

- [ ] **Step 2: fallback build once**

`make test X2APIC=0` — confirm `[lapic] xapic (mmio) mode`, all
selftests green. (Not part of the gauntlet; a one-time check.)

- [ ] **Step 3: ID-plumbing audit**

`grep -rn '<< 24\|>> 24\|(uint8_t).*apic\|apic.*uint8' kernel/` — every
hit is either the MMIO `lapic_id()` shift (now guarded) or the MADT
on-disk `uint8_t` (fine). Fix any raw 8-bit APIC-id assumption in the
IPI or IOAPIC destination code; note IOAPIC RTE destination stays
≤8 bits for physical mode with ≤255 CPUs (unchanged).

- [ ] **Step 4: gauntlet ×3 + commit**

`"x2APIC: self-IPI selftest; ID plumbing audit"`.
